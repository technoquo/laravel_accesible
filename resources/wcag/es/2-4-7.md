## Qué exige

Cualquier interfaz que se pueda usar con el teclado tiene que mostrar un indicador visible del elemento que tiene el foco.

## Por qué importa

Sin indicador de foco, quien navega con teclado no sabe dónde está: es como usar el ratón sin ver el puntero.

## Cómo cumplirlo en Laravel

Nunca quites el contorno de foco sin poner otro en su lugar. Este blog define un indicador global en `app.css`:

```css
@layer base {
    *:focus-visible {
        outline: 2px solid currentColor;
        outline-offset: 3px;
        border-radius: 2px;
    }
}
```

`:focus-visible` muestra el indicador al navegar con el teclado y no al hacer clic con el ratón.

En los componentes, si usas `focus:outline-none` de Tailwind, añade siempre un sustituto visible:

```blade
<button type="submit"
        class="rounded bg-gray-900 px-4 py-2 text-white
               focus:outline-none focus-visible:ring-2 focus-visible:ring-offset-2 focus-visible:ring-gray-900">
    Guardar
</button>
```

Asegúrate de que el indicador también se ve en modo oscuro y en los modos de alto contraste: usar `currentColor` ayuda, porque sigue el color del texto.

## Errores frecuentes

- `outline: none` en un reset CSS global.
- `focus:outline-none` sin `ring` ni otro estilo de foco.
- Un indicador del mismo color que el fondo en uno de los temas.

## Cómo probarlo

- **Manual:** recorre la página con `Tab` en cada tema (claro, oscuro, alto contraste) y comprueba que siempre ves dónde está el foco.
- **Automático:** axe no comprueba este criterio. Puedes hacer capturas con Playwright del elemento enfocado para revisarlas.
