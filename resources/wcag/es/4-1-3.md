## Qué exige

Los mensajes de estado —que informan del resultado de una acción, del progreso, de un error o de que algo está esperando— tienen que poder anunciarse a las tecnologías de apoyo **sin recibir el foco**.

## Por qué importa

Cuando Livewire guarda un formulario sin recargar la página y muestra «Guardado», quien ve la pantalla lo nota; quien usa lector de pantalla no se entera si el mensaje no está en una región viva (*live region*). Mover el foco al mensaje tampoco es buena idea: saca a la persona de donde estaba trabajando.

## Cómo cumplirlo en Laravel

Usa los roles de región viva:

- `role="status"` para mensajes informativos: espera a que el lector termine lo que está diciendo.
- `role="alert"` para avisos importantes que deben interrumpir, como un error al guardar.

La clave es que **la región exista antes** de que cambie su contenido. Si la región entera aparece de golpe, algunos lectores no la anuncian.

```blade
{{-- La región está siempre en el DOM; solo cambia el texto --}}
<div role="status" class="text-sm text-green-800">
    {{ $statusMessage }}
</div>

<button type="button" wire:click="save">Guardar</button>
```

```php
public string $statusMessage = '';

public function save(): void
{
    $this->statusMessage = '';
    $this->validate();

    // ... guardar

    $this->statusMessage = 'Cambios guardados.';
}
```

Otros mensajes de estado frecuentes:

- **Resultados de búsqueda o filtros:** «12 artículos encontrados».
- **Carga:** «Cargando más resultados…» con `wire:loading` dentro de una región `role="status"`.
- **Carrito o contadores:** «Producto añadido. 3 productos en el carrito».

Tras una redirección con recarga completa (por ejemplo, `session()->flash()` y `redirect()`), el mensaje forma parte de la nueva página y no es un cambio dinámico: no se anuncia solo. En ese caso, colócalo al principio del contenido principal o lleva el foco a su encabezado.

## Errores frecuentes

- Insertar el contenedor `role="status"` con `@if`, en lugar de dejarlo siempre presente.
- Usar `role="alert"` para todo: interrumpe continuamente.
- Mensajes `sr-only` que las personas que ven la pantalla no reciben.

## Cómo probarlo

- **Manual:** con NVDA o VoiceOver, lanza cada acción y comprueba que el mensaje se anuncia sin que el foco se mueva.
- **Automático:** axe no comprueba este criterio. Con Pest o Livewire puedes comprobar que la región existe y contiene el texto tras la acción:

```php
Livewire::test(PostSettings::class)
    ->call('save')
    ->assertSet('statusMessage', 'Cambios guardados.');
```
