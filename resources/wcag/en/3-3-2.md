## What it requires

Fields and controls that request input must provide visible labels or instructions: what to enter, in which format and whether it is required.

## Why it matters

Without a visible label, nobody knows for sure what each field asks for, least of all people with cognitive or memory difficulties. A `placeholder` is not a label: it disappears as you type and usually has low contrast.

## How to meet it in Laravel

Give every field a visible `<label>` and, when needed, instructions linked with `aria-describedby`:

```blade
<label for="published_at">
    Publication date
    <span class="text-sm text-gray-700">(required)</span>
</label>
<p id="published_at-hint" class="text-sm text-gray-700">Format: day/month/year, for example 15/03/2026.</p>
<input type="text" id="published_at" name="published_at" required
       aria-describedby="published_at-hint">
```

- Mark required fields with text. If you use an asterisk, explain what it means at the top of the form.
- Give format instructions **before** the field, not only in the error message.
- Group related options with `<fieldset>` and `<legend>`, which acts as the group's label.
- For single-field search forms, a visually hidden label (`sr-only`) is acceptable if the "Search" button makes the purpose clear.

A Blade component avoids repeating the pattern:

```blade
{{-- resources/views/components/field.blade.php --}}
@props(['name', 'label', 'hint' => null])

<div>
    <label for="{{ $name }}">{{ $label }}</label>
    @if ($hint)
        <p id="{{ $name }}-hint" class="text-sm text-gray-700">{{ $hint }}</p>
    @endif
    <input id="{{ $name }}" name="{{ $name }}"
           @if ($hint) aria-describedby="{{ $name }}-hint" @endif
           {{ $attributes }}>
</div>
```

## Common mistakes

- Using `placeholder` as the only label.
- Required fields marked only with colour.
- Explaining the format only after the mistake has been made.

## How to test it

- **Manual:** look at the form with all fields filled in: can you still tell what each one is? Go through it with a screen reader and check that each field announces its label and instructions.
- **Automated:** axe detects fields without an accessible name (`label`, a 4.1.2 rule) and fields with several labels (`form-field-multiple-labels`), but not whether the instructions are enough.
