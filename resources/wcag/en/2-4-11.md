## What it requires

When an element receives focus, it must not be **entirely** hidden by author-created content such as a sticky header, a cookie banner or a chat widget. Being partly covered does not fail this Level AA criterion (it does fail 2.4.12, Level AAA).

It is new in WCAG 2.2.

## Why it matters

Keyboard users can only see where focus is if the element is in view. With a sticky header, pressing `Tab` can make the browser scroll the page and leave the focused element right under the header, invisible.

## How to meet it in Laravel

If the header is sticky or fixed, reserve its height in scrolling with `scroll-padding-top`:

```css
/* resources/css/app.css */
html {
    scroll-padding-top: 5rem; /* height of the sticky header */
}
```

When the browser scrolls to show the focused element, it then places it below the header.

For fixed banners and notices:

- Position them so they do not cover content, or reserve space for them (for example, `padding-bottom` on `<body>` while they are visible).
- Let people close them with a keyboard-accessible button.

## Common mistakes

- Tall sticky headers without `scroll-padding-top`.
- Fixed cookie banners covering the last links on the page.
- Floating chat buttons over form controls.

## How to test it

- **Manual:** go through the page with `Tab`, and backwards with `Shift + Tab`, and check that the focused element is always visible. Repeat with text at 200% and on narrow screens, where headers take up more space.
- **Automated:** axe does not check it. With Playwright you can compare the focused element's position with the header's using `boundingBox()`.
