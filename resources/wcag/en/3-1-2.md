## What it requires

Each passage or phrase written in a language other than the page's must have its own language set in the markup, with the `lang` attribute.

Proper names, technical terms, words of indeterminate language and words that have become part of the surrounding language (such as "fiesta" in English) do not need to be marked.

## Why it matters

Without `lang`, a screen reader reads a Spanish quote using English rules, and the result is unintelligible. With `lang`, it switches voice or pronunciation just for that passage.

## How to meet it in Laravel

Mark the passage with its language:

```blade
<p>
    As the disability rights motto says in Spanish:
    <q lang="es">Nada sobre nosotros sin nosotros</q>.
</p>
```

A typical case on bilingual sites is the language switcher: each option is written in its own language.

```blade
<nav aria-label="{{ __('ui.lang_selector') }}">
    <a href="/es" lang="es" hreflang="es">Español</a>
    <a href="/en" lang="en" hreflang="en">English</a>
</nav>
```

In the English version of this blog's About page, Spanish names of events and projects are marked with `lang="es"`. Proper names are exempt, but marking them improves pronunciation.

If content comes from Markdown, you can write the passage as a normal quote and set the language in the template, or allow `<span lang>` in the renderer if the content is trusted.

## Common mistakes

- Quotes, book titles or long Spanish phrases left unmarked inside English text.
- Language switchers without `lang` on each option.
- Using `hreflang` as if it replaced `lang`: `hreflang` describes the language of the link destination, not of the text.

## How to test it

- **Automated:** axe only checks that `lang` values are valid (`valid-lang`); it cannot know which passages are in another language.
- **Manual:** read the page looking for phrases in other languages and listen to them with a screen reader.
