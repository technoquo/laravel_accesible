## What it requires

Information and relationships conveyed through visual presentation —headings, lists, tables, groups of fields, labels— must also be present in the markup, or in the text, so assistive technology can recognise them.

## Why it matters

Screen reader users navigate by headings, jump between lists and move through tables cell by cell. If a title is just a `<div>` in a large font, or a table does not mark its headers, that structure does not exist for them.

## How to meet it in Laravel

Use the HTML element that matches the meaning, not the look:

```blade
<h2 class="text-xl font-semibold">Recent articles</h2>

<ul role="list">
    @foreach ($posts as $post)
        <li>{{ $post->title }}</li>
    @endforeach
</ul>
```

Data tables need real headers and a caption:

```blade
<table>
    <caption>Published articles</caption>
    <thead>
        <tr>
            <th scope="col">Title</th>
            <th scope="col">Status</th>
        </tr>
    </thead>
    <tbody>
        @foreach ($posts as $post)
            <tr>
                <th scope="row">{{ $post->title }}</th>
                <td>{{ $post->published_at ? 'Published' : 'Draft' }}</td>
            </tr>
        @endforeach
    </tbody>
</table>
```

Group related fields, such as a set of options, with `<fieldset>` and `<legend>`:

```blade
<fieldset>
    <legend>Article status</legend>
    <label><input type="radio" wire:model="status" value="draft"> Draft</label>
    <label><input type="radio" wire:model="status" value="published"> Published</label>
</fieldset>
```

Keep the heading hierarchy (one `<h1>` per page and no skipped levels) and use the layout landmarks (`<header>`, `<nav>`, `<main>`, `<footer>`).

## Common mistakes

- Headings made with a bold `<div>` or `<p>`.
- Lists made with `<br>` or with paragraphs that start with a dash.
- Tables used for layout, or data tables without `<th>`.
- Fields in the same group without a `<fieldset>`, so the shared question is never announced.

## How to test it

- **Automated:** axe checks the structure of lists, tables and definition lists (`list`, `listitem`, `th-has-data-cells`, `td-headers-attr`…).
- **Manual:** open the screen reader's headings list (in NVDA, `Insert + F7`) and check that it reflects the page structure; turn off CSS and check that the content still makes sense.
