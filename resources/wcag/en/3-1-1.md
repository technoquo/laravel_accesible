## What it requires

The main language of each page must be programmatically determinable, that is, set in the `lang` attribute of the `<html>` element.

## Why it matters

Screen readers choose the voice and pronunciation rules from the declared language. If a Spanish page is declared as English, the text is read with an English accent and is almost incomprehensible. Automatic translators, dictionaries and spell checkers use it too.

## How to meet it in Laravel

The layout Laravel generates already does this from the application locale:

```blade
<html lang="{{ str_replace('_', '-', app()->getLocale()) }}">
```

On a bilingual site, set the locale **before** the view renders; for example, with middleware that reads it from the URL:

```php
// app/Http/Middleware/SetLocale.php
public function handle(Request $request, Closure $next): Response
{
    $locale = $request->route('locale');

    abort_unless(in_array($locale, ['es', 'en'], true), 404);

    app()->setLocale($locale);

    return $next($request);
}
```

Use valid language codes (`es`, `en`, `es-CR`, `en-GB`), not translation file names if they do not match a BCP 47 code.

## Common mistakes

- Leaving `lang="en"` hard-coded in a layout that also serves Spanish content.
- Changing the locale after the view has started rendering.
- Invalid codes such as `lang="spanish"` or `lang="en_GB"` with an underscore.

## How to test it

- **Automated:** axe checks that `<html>` has `lang` and that the value is valid (`html-has-lang`, `html-lang-valid`, `html-xml-lang-mismatch`). With Pest you can check it for each locale:

```php
test('the page declares its language', function (string $locale) {
    $this->get("/{$locale}")->assertSee('<html lang="'.$locale.'"', false);
})->with(['es', 'en']);
```

- **Manual:** listen to the page with a screen reader and check that the pronunciation matches the language.
