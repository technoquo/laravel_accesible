## What it requires

Every user interface component must expose to assistive technology its **name** (what it is), its **role** (button, checkbox, tab…) and its **state or value** (checked, expanded, selected). When the state changes, the change must also be notified.

## Why it matters

A screen reader announces "Menu, button, collapsed" because the markup tells it so. A `<div>` acting as a button is announced as plain text; a disclosure that does not update its state leaves the person not knowing whether it opened.

## How to meet it in Laravel

**Use native elements whenever you can.** `<button>`, `<a href>`, `<input type="checkbox">` or `<select>` already come with name, role and state.

**Give icon-only controls a name:**

```blade
<button type="button" wire:click="toggleMenu">
    <svg aria-hidden="true" focusable="false"><!-- ... --></svg>
    <span class="sr-only">Menu</span>
</button>
```

**In custom components, keep the ARIA state in sync with the real state.** With Alpine, bind the attribute to the variable:

```blade
<div x-data="{ open: false }">
    <button type="button"
            x-on:click="open = ! open"
            x-bind:aria-expanded="open"
            aria-controls="filters-panel">
        Filters
    </button>
    <div id="filters-panel" x-show="open">...</div>
</div>
```

Alpine writes `aria-expanded="false"` instead of removing the attribute when the value is false, so the state is always present.

With Livewire, if the state lives on the server, print it in the view:

```blade
<button type="button" wire:click="toggleFavorite" aria-pressed="{{ $isFavorite ? 'true' : 'false' }}">
    Favourite
</button>
```

**If there is no native element** (tabs, trees, composite menus), follow the ARIA Authoring Practices Guide pattern: role, states and keyboard behaviour go together.

## Common mistakes

- `<div>` or `<span>` with `wire:click` instead of `<button>`.
- Icon buttons without an accessible name.
- `aria-expanded` that does not change when opening or closing.
- Invented or misspelt ARIA roles (`role="buton"`).

## How to test it

- **Automated:** axe has many rules for this criterion (`button-name`, `link-name`, `label`, `aria-valid-attr-value`, `aria-required-attr`, `nested-interactive`…).
- **Manual:** go through the components with a screen reader and check that each one announces its name, role and state, and that the state changes when you interact. The accessibility panel in DevTools shows the accessibility tree.
