## What it requires

If a page can be navigated sequentially and the order affects meaning or operation, elements must receive focus in an order that preserves that meaning and operability.

## Why it matters

Keyboard users move from element to element. If focus jumps from the header to the footer, goes behind an open modal, or returns to the top after every action, the page becomes confusing or unusable.

## How to meet it in Laravel

- **DOM order = visual order.** Write the HTML in reading order. If you reorder with CSS (`order`, `flex-row-reverse`, absolute positioning), focus still follows source order, not visual order.
- **Do not use positive `tabindex`** (`tabindex="1"`, `"2"`…): it breaks the natural order. Only use `0` (add to the order) and `-1` (focusable only programmatically).
- **Modal windows:** with the `<dialog>` element and `showModal()`, the rest of the page becomes inert and focus moves into the dialog; when it closes, browsers return focus to the element that opened it.

```blade
<div x-data>
    <button type="button" x-on:click="$refs.confirm.showModal()">Delete article</button>

    <dialog x-ref="confirm" aria-labelledby="confirm-title">
        <h2 id="confirm-title">Delete the article?</h2>
        <button type="button" wire:click="delete" x-on:click="$refs.confirm.close()">Delete</button>
        <button type="button" x-on:click="$refs.confirm.close()">Cancel</button>
    </dialog>
</div>
```

- **Livewire updates:** do not remove the focused element and, when new content appears, move focus to it intentionally. We explain this in the article on keyboard navigation in Livewire.

## Common mistakes

- Modals built with a `<div>` that leave focus behind them.
- Side menus that are visually hidden but still focusable (use `inert` or `hidden`).
- Columns reordered with CSS on mobile.

## How to test it

- **Manual:** go through the page with `Tab`, watching where focus is at each step; open and close modals and menus, and trigger Livewire actions.
- **Automated:** axe cannot judge whether the order is logical. With Playwright you can check specific flows, for example that focus returns to the button after closing a dialog (`await expect(button).toBeFocused()`).
