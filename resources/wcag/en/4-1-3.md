## What it requires

Status messages —which report the result of an action, progress, an error or that something is waiting— must be announceable by assistive technology **without receiving focus**.

## Why it matters

When Livewire saves a form without reloading and shows "Saved", sighted users notice it; screen reader users miss it if the message is not in a live region. Moving focus to the message is not a good idea either: it takes the person away from where they were working.

## How to meet it in Laravel

Use live region roles:

- `role="status"` for informative messages: it waits until the reader finishes what it is saying.
- `role="alert"` for important notices that should interrupt, such as a save error.

The key is that **the region exists before** its content changes. If the whole region appears at once, some screen readers do not announce it.

```blade
{{-- The region is always in the DOM; only the text changes --}}
<div role="status" class="text-sm text-green-800">
    {{ $statusMessage }}
</div>

<button type="button" wire:click="save">Save</button>
```

```php
public string $statusMessage = '';

public function save(): void
{
    $this->statusMessage = '';
    $this->validate();

    // ... save

    $this->statusMessage = 'Changes saved.';
}
```

Other common status messages:

- **Search or filter results:** "12 articles found".
- **Loading:** "Loading more results…" with `wire:loading` inside a `role="status"` region.
- **Cart or counters:** "Product added. 3 products in your cart".

After a redirect with a full page load (for example, `session()->flash()` and `redirect()`), the message is part of the new page and is not a dynamic change: it is not announced on its own. In that case, place it at the top of the main content or move focus to its heading.

## Common mistakes

- Inserting the `role="status"` container with `@if` instead of keeping it always present.
- Using `role="alert"` for everything: it interrupts constantly.
- `sr-only` messages that sighted users never get.

## How to test it

- **Manual:** with NVDA or VoiceOver, trigger each action and check that the message is announced without focus moving.
- **Automated:** axe does not check this criterion. With Pest and Livewire you can check that the message is set after the action:

```php
Livewire::test(PostSettings::class)
    ->call('save')
    ->assertSet('statusMessage', 'Changes saved.');
```
