## What it requires

Targets activated with a pointer (mouse, finger, stylus) must be at least **24 × 24 CSS px**. It is new in WCAG 2.2.

There are exceptions:

- **Spacing:** a smaller target passes if a 24 px diameter circle centred on it does not intersect another target or its circle.
- **Inline:** links within a paragraph of text.
- **Equivalent:** another control does the same thing and meets the size.
- **User agent control:** the size is set by the browser and the author has not changed it.
- **Essential:** the size is essential, such as points on a map.

## Why it matters

Small, tightly packed targets cause mistaken taps for people with tremors, limited mobility or anyone using a phone with one hand.

## How to meet it in Laravel

In Tailwind CSS, `size-6` and `min-h-6 min-w-6` equal 24 px (1.5rem). For icon buttons it is worth going further:

```blade
<button type="button"
        class="inline-flex size-10 items-center justify-center rounded"
        wire:click="toggleFavorite">
    <svg aria-hidden="true" focusable="false" class="size-5"><!-- ... --></svg>
    <span class="sr-only">Add to favourites</span>
</button>
```

The icon can be small: what counts is the button's area.

- Separate icons in an action bar with `gap-2` or more.
- In tag lists or pagination, make sure each link has enough `padding`.
- Native checkboxes and radio buttons use the browser's size; if you enlarge them with CSS (`size-5`), wrap them in a `<label>` that is also clickable.

## Common mistakes

- 16 × 16 px icon buttons without `padding`.
- Pagination with tightly packed numbers.
- Tiny "×" buttons to close notices.

## How to test it

- **Automated:** axe's `target-size` rule (tag `wcag22aa`) checks size and spacing.
- **Manual:** measure targets with DevTools and try the interface on a real phone.
