## What it requires

When an input error is automatically detected, the field in error must be identified and the error described in text.

## Why it matters

A red border tells nothing to a blind or colour-blind person, and a generic message ("There are errors in the form") forces people to review every field without knowing which one failed.

## How to meet it in Laravel

Laravel validation already produces one message per field; you only need to show it next to the field and link it:

```blade
<label for="email">Email address</label>
<input type="email" id="email" name="email" value="{{ old('email') }}"
       @error('email') aria-invalid="true" aria-describedby="email-error" @enderror>
@error('email')
    <p id="email-error" class="text-sm text-red-700">{{ $message }}</p>
@enderror
```

- `aria-invalid="true"` makes the reader announce the field as invalid.
- `aria-describedby` makes it read the message when the field gets focus.

After a classic submission that reloads the page, the messages are no longer a dynamic change and are not announced on their own. Show a summary at the top of the form and move focus to it, so the reader reads it immediately:

```blade
@if ($errors->any())
    <div id="error-summary" tabindex="-1" class="rounded border border-red-700 p-4">
        <h2>Fix the errors in the form</h2>
        <ul>
            @foreach ($errors->keys() as $field)
                <li><a href="#{{ $field }}">{{ $errors->first($field) }}</a></li>
            @endforeach
        </ul>
    </div>
    <script>document.getElementById('error-summary').focus();</script>
@endif
```

With Livewire, where there is no reload, errors appear next to each field; see guide 4.1.3 and the article on error messages in Livewire.

Write messages that explain the problem in plain language. You can customise them in `lang/en/validation.php` or in the `FormRequest`.

## Common mistakes

- Signalling the error only with colour (red border).
- Messages not linked to the field in the markup (no `aria-describedby`).
- Messages in a different language from the page.

## How to test it

- **Manual:** submit the form empty and with wrong data; with a screen reader, check that focusing each field announces "invalid" and the message.
- **Automated:** with Pest, check that validation returns the field's error:

```php
$this->post(route('register'), [])
    ->assertSessionHasErrors('email');
```
